# Which version of each sibling project this repository builds against.
#
# Replaces VENDOR_PINS.txt, which recorded submodule gitlinks — arbitrary
# commits like v0.1.3-18-g2e5da31, eighteen commits past a release, so
# "which version is in the app" had no answer anyone could say out loud.
#
# The siblings are checkouts beside this repository now. scripts/sibling-build.sh
# builds each one: from its checkout when that is on a clean main, and otherwise
# from a throwaway worktree of the ref named here, so a developer's branch
# cannot reach the app's binary. A dirty main stops the build rather than
# guessing what it meant.
#
# TAGS, not branches. The build contract lives in each project's chores.yml,
# so a pin can only name a tag that contains one — which is why this said
# `main` until 2026-08-29, when the whole family was released.
#
# The chore version CI installs. The build contract is expressed in each
# project's chores.yml, so the tool that reads it is a pinned input like
# any other.
#
# This pin is this repository's own: the exact release ci.yml and release.yml
# download, and the only place either of them reads it from. It is
# not a version for the family. Each sibling declares the oldest chore that
# can read its contract as `chore_min_version` in its own chores.yml, and
# installs what it installs; this line decides nothing for them (#79). It
# must sit at or above this repository's chore_min_version, and at or above the
# floor of the go-networkfs ref pinned below, the one sibling chore builds
# here. scripts/check-chore-pin.sh holds the first two to that.
chore               0.8.0

# -------           ---
go-networkfs        v0.1.5
